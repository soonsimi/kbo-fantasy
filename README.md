# KBO 판타지 리그

KBO 선수 스탯을 기반으로 하는 로토서리(Rotisserie) 방식 판타지 리그 웹 애플리케이션.

- **방식**: 시즌 누적 점수제 (로토서리)
- **규모**: 8~12명
- **드래프트**: 시즌 초 1회

## 산정 규칙

### 부문 (15개)

`−` 표시는 값이 **적을수록** 상위 순위를 받는 부문이다.

| 구분 | 부문 |
| --- | --- |
| 타자 (8) | R(득점), H(안타), HR(홈런), RBI(타점), SB(도루), BB(볼넷), SO(삼진) −, GDP(병살타) − |
| 투수 (7) | W(승), L(패) −, SV+HLD(세이브+홀드), IP(이닝), H(피안타) −, BB(볼넷) −, SO(탈삼진) |

H와 BB는 역할에 따라 방향이 반대다. 타자의 안타·볼넷은 많아야 좋고,
투수의 피안타·볼넷은 적어야 좋다. 열 이름 매핑도 같은 이유로 역할별로 분리되어 있다
(`src/import/columns.ts`).

### 월별 순위

- 부문마다 참가자끼리 순위를 매기고, 그 순위에 **역순으로** 점수를 준다.
  9인 리그면 1위 9점 ~ 9위 1점.
- 동점자는 차지한 점수 구간을 균등 배분한다. 1위 동점 2명이면 (9+8)/2 = 8.5점씩.
- 부문 점수의 합이 그 달의 총점이고, 총점 순서가 그 달의 순위다.
- 한 달 만점 = 15부문 × 인원수. 9인 리그면 135점.

### 시즌 종합 순위

**월별 순위의 합산**이다. 합이 작을수록 상위.

예) 4월 3위 + 5월 1위 + 6월 2위 = 6. 다른 참가자가 5면 그 쪽이 상위.

꾸준히 2위를 하는 참가자가 1위와 3위를 오가는 참가자를 이길 수 있는 방식이다.
기록이 없는 달은 산정에서 제외한다.

> **인원 변경 주의**: 월 순위 합산은 인원수가 유지될 때만 달끼리 공평하다.
> 9명이던 달의 최하위는 9위지만 8명인 달의 최하위는 8위여서, 같은 성적이라도
> 달마다 유불리가 생긴다. 인원은 시즌 시작 전에 확정하는 것이 안전하다.
> 리그 설정 화면에서 기록이 이미 있으면 경고를 띄운다.

### 기타

동점 판정은 **화면에 표시되는 값** 기준이다. 내부 실수로 미세하게 갈리면
참가자에게는 같은 값으로 보이는데 점수가 달라져 분쟁이 된다.

부문을 추가·삭제하려면 `src/domain/categories.ts`의 배열만 고치면 된다.
산정 엔진, 임포트에 필요한 열 목록, 순위표 열이 모두 이 정의에서 도출된다.

이닝은 `159 2/3` 같은 분수 표기와 `159.2` 형태를 모두 받아 소수로 정규화한다.
야구 관례상 소수점 한 자리의 `.1`/`.2`는 1/3, 2/3을 뜻하므로 그대로 실수로 읽으면
이닝 합계가 틀어진다 (`src/domain/innings.ts`).

현재 부문은 전부 누적 카운팅 스탯이라 팀 값은 단순 합이다. 나중에 타율·평균자책점처럼
비율 부문을 넣을 때는 분모(AB, IP)까지 합산한 뒤 나눠야 한다. 선수별 비율을 평균내면
틀린다 — 타율 .400인 10타수 선수와 .250인 500타수 선수의 팀 타율은 .325가 아니라 .253이다.

## 화면 구성

| 탭 | 하는 일 |
| --- | --- |
| 순위표 | 시즌 종합(월 순위 합산)과 월별 상세 순위 |
| 리그 설정 | 참여 인원 등록·이름 수정·순서 변경. 인원수에 따른 만점 표시 |
| 드래프트 결과 | 오프라인 드래프트 결과를 일괄 입력. 참가자별 로스터 조정 |
| 스탯 불러오기 | 달을 골라 표를 붙여넣기 |

드래프트는 오프라인에서 진행하고 결과만 옮겨 적는다. 한 명씩 검색해 지명하면
12명 × 20명 = 240번을 클릭해야 하므로, 다음 형식으로 한 번에 넣는다:

```
홍길동: 김도영, 구자욱, 원태인
이몽룡: 레이예스, 오스틴, 네일
```

탭 구분과 `이름 - 선수1` 형식도 된다. 같은 선수를 두 명에게 배정하면 막고,
명단에 없는 이름은 따로 보고한다.

## 데이터 입력 방식

**자동 크롤링은 하지 않는다.** KBO 공식 사이트와 스탯티즈 모두 robots.txt에서
목적 구분 없이 봇 접근을 전면 차단하고 있다.

```
# koreabaseball.com/robots.txt
# 본 사이트의 데이터를 사전 승인 없이 자동 수집·복제하는 행위를 금지합니다.
User-agent: *
Disallow: /
```

```
# statiz.co.kr/robots.txt (Cloudflare 관리 블록 이후, 운영자 작성 영역)
# 그 외 모든 봇 차단
User-agent: *
Disallow: /
```

대신 브라우저에서 직접 열람한 표를 복사해 붙여넣는다. 시즌 누적 방식이라
**주 1회 갱신으로 충분**하고, 필요한 범위도 리그에 지명된 선수(12명 × 20명 ≈ 240명)뿐이다.
CSV 파일 업로드도 지원한다.

### 월별 입력

스탯은 **달별로** 저장한다. 순위 산정이 월 단위라 시즌 누적만 갖고 있으면
월별 순위를 되돌려 계산할 수 없기 때문이다.

붙여넣을 때 두 가지 모드를 고른다:

| 모드 | 쓰는 경우 |
| --- | --- |
| `한 달치 기록` | 그 달만의 기록 표를 구했을 때. 값을 그대로 저장한다. |
| `시즌 누적` | 누적 표만 구할 수 있을 때. 이전 달들의 합을 빼서 그 달 값을 만든다. |

누적 모드는 이전 달 기록이 먼저 들어와 있어야 정확하다. 누적값이 이전 달 합보다
작으면 (달을 잘못 골랐거나 표가 누적이 아닌 경우) 0으로 처리하고 경고한다.

### 부분 임포트

필요한 항목이 한 페이지에 다 없다. KBO 기록실은 타자 R·H·HR·RBI·SB가 기본기록1,
BB·SO·GDP가 기본기록2에 나뉘어 있다. 그래서 임포트는 **표에 있는 열만 덮어쓰고
나머지는 그대로 두는** 방식이다. 표를 차례로 넣으면 열이 하나씩 채워진다.

- 어느 항목이 아직 안 들어왔는지 달마다 화면에서 보여준다 (`importedFields`로 추적).
  값이 0인 것과 아직 안 넣은 것은 구별해야 하기 때문이다 —
  안 넣은 부문은 전원 0이 되어 그 달 순위가 왜곡된다.
- 빈 칸은 0으로 덮어쓰지 않고 건드리지 않는다.
- 같은 표를 다시 넣어도 누적되지 않고 갱신된다.

임포트 계층은 `ParseResult`를 돌려주는 어댑터로 분리되어 있다
(`src/import/parseStatTable.ts`). 정식 데이터 제공 경로가 열리면 같은 형태를
반환하는 모듈만 추가하면 되고 도메인·UI는 그대로 쓴다.

```bash

```

Firebase 설정 없이 바로 실행된다 (localStorage에 저장).

## Firestore 연결

리그 참가자끼리 데이터를 공유하려면 Firebase를 붙인다.

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트 생성
2. Firestore Database 활성화
3. **Authentication에서 로그인 방법을 하나 이상 활성화** (Google 또는 익명)
   — `firestore.rules`가 쓰기에 로그인을 요구하므로, 안 하면 저장 시 `permission-denied`가 난다
4. `.env.example`을 `.env.local`로 복사하고 값 입력
5. 보안 규칙 배포: `firebase deploy --only firestore:rules`

`.env.local`이 채워지면 저장소가 자동으로 Firestore로 바뀌고, 다른 참가자의 변경이
실시간으로 반영된다. Firebase SDK는 설정이 있을 때만 동적으로 로드되므로
localStorage 모드에서는 번들에 포함되지 않는다.

Firebase 웹 API 키는 비밀값이 아니라 프로젝트 식별자다. 실제 접근 통제는
`firestore.rules`가 담당한다 — 저장소가 Public이므로 규칙이 유일한 방어선이다.

## 구조

```
src/
  domain/         순수 도메인 로직 (저장소·UI 의존 없음)
    types.ts        누적 원시 스탯 타입, 월 키 유틸
    categories.ts   부문 정의 — 부문을 바꾸려면 이 파일만 고친다
    rotisserie.ts   한 기간의 순위 산정 엔진
    season.ts       월별 순위 + 시즌 종합(월 순위 합산)
    innings.ts      이닝 표기 파싱·표시
  import/         입력 파싱
    columns.ts      열 이름 → 필드 매핑 (타자/투수 역할별로 분리)
    parseStatTable.ts  스탯 표 파싱
    parseDraft.ts      드래프트 결과 일괄 입력 파싱
    applyImport.ts     파싱 결과를 특정 달에 병합 (월간/누적 모드)
  data/           저장소 (인터페이스 + localStorage/Firestore 구현)
  components/     화면
  useLeague.ts    저장소 연동 훅
```

순위 계산은 `LeagueSnapshot` 하나만 입력받는 순수 함수라, 저장 위치를 바꿔도
산정 로직은 영향받지 않는다.

## 아직 없는 것

- **로스터 상한·포지션 제약**: 팀당 인원이나 타자/투수 구성을 검증하지 않는다.
- **월별 순위 발표 이력**: 발표 시점을 기록해 두지 않는다. 지금 데이터로 다시 계산할 뿐이라,
  나중에 기록을 수정하면 과거 달 순위도 함께 바뀐다.
- **종합 순위 동점 처리 규칙**: 월 순위 합이 같으면 공동 순위로 둔다.
  따로 정한 타이브레이커가 없다 (총점 합을 참고용으로 표시만 한다).
- **인증 연동 화면**: 규칙은 로그인을 요구하지만 앱에 로그인 UI가 없다.
  Firestore로 전환할 때 함께 붙여야 한다.
